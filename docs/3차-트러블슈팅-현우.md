## 9/16 클러스터를 올리고 끄는 중

### EKS stop이 성공인데 워커가 살아 있음

- 증상: Actions stop은 초록인데 EC2 워커와 NAT가 Running.
- 원인: 노드그룹 desired=0만 호출하고 끝났고, ASG가 실제로 0이 됐는지 확인하지 않았다. Cluster Autoscaler가 남은 max 여유로 노드를 다시 올렸다. `maxSize=0`은 EKS API가 거절한다 (최소 1).
- 조치: desired=0, max=1을 유지하고 ASG Launch를 suspend 한다. ASG DesiredCapacity를 0으로 맞춘 뒤 인스턴스가 0이 될 때까지 기다리고, NAT도 같이 끈다. start는 NAT를 먼저 켠다.
- 워크플로에 클러스터·노드그룹 이름이 없으면 즉시 실패했다. 기본값을 `aniverse-eks` / `aniverse-nodes`로 넣었다.

### DB 복구 Job이 멈추거나 클라이언트가 없음

- 증상: SQL 자동 복구가 Argo sync에 묶이거나, ConfigMap에 덤프를 넣다 실패. 이어서 `mysqladmin`이 없다고 죽는다.
- 원인: Sync hook이 operation을 붙잡는다. ConfigMap은 256Ki 한도가 있어 SQL 덤프가 들어가지 않는다. MariaDB 11 이미지에는 `mysqladmin`이 없고 `mariadb-admin`만 있다.
- 조치: hook을 뺀 일반 Job으로 바꾸고, 덤프는 Git raw URL을 curl로 받는다. ready 체크는 `mariadb-admin`. curl 설치는 복구가 필요할 때만 한다.

### SQL은 복구됐는데 사진이 없음

- 증상: 글 목록은 뜨고 goods/works 이미지는 깨진다.
- 원인: DB에는 경로만 있다. 버킷을 destroy하면 객체는 사라진다.
- 조치: DB Job과 별도로 media/static을 S3에 다시 올린다. wipe 검증과 sync가 동시에 돌면 지운 직후 파일이 다시 생기므로 같은 concurrency group으로 직렬화했다.

### 헬스체크와 Helm 값

- 증상: `/health/`가 `DisallowedHost`. 호스트를 여러 개 넣으면 `ALLOWED_HOSTS`가 잘린다.
- 원인: 프로브 Host가 파드 IP라 Django가 거절한다. Helm `--set`는 쉼표를 구분자로 쓴다.
- 조치: 프로브에 `Host: aniverse.my`를 넣고 ALLOWED_HOSTS를 보강한다. 쉼표가 있는 값은 values 파일에만 둔다.

### state에 없는 기존 리소스

- 증상: ECR `AlreadyExists`. 로컬 kubectl이 클러스터에 못 들어간다.
- 원인: 이미 만든 ECR과 iac-admin Access Entry가 Terraform state 밖에 있다. 인증 모드가 API라 Access Entry가 없으면 kubectl이 거절된다.
- 조치: ECR과 Access Entry를 import하고, 로컬용 `eks-grant-me-admin.sh`로 권한을 준다.

## 9/18 계정 Block과 destroy

### 계정 Block

- 증상: 콘솔과 Actions 모두 `StartInstances`가 `Blocked`.
- 원인: EKS start 스크립트가 아니다. `iac-admin` 장기 액세스 키가 유출된 뒤, 승인되지 않은 `RunInstances`가 나가면서 계정 `679583587966`이 막혔다. 이후 운영 계정은 `841535407395`다.
- 조치: 유출 키 삭제, 무단 리소스 정리, Support 회신. CI는 OIDC만 쓴다. 키 값은 문서에 적지 않는다.

### destroy가 중간에 죽어 다음 plan이 막힘

- 증상: 노드그룹 `DELETE_FAILED`, 서브넷·IGW `DependencyViolation`, VPC가 10분 넘게 삭제 중, 재실행은 state lock에서 즉시 실패.
- 원인: API 인증인데 노드 Access Entry가 없으면 drain 권한이 없어 노드그룹 삭제가 실패한다. Ingress ALB는 Terraform 밖이라 ENI가 서브넷을 붙잡는다. preflight가 ReplaceUnhealthy를 suspend하면 EKS가 노드그룹 삭제를 거절한다. 취소된 destroy가 S3 lock을 남긴다. `aws_vpc` timeouts 블록은 이 프로바이더에서 지원되지 않는다.
- 조치: destroy 전에 고아 ALB와 노드 Access Entry를 치운다. 삭제 전에 ReplaceUnhealthy를 resume하고, `DELETE_FAILED` 노드그룹은 ASG와 CloudFormation으로 강제 삭제한다. VPC 삭제 전에 ENI를 지우고 타임아웃을 늘린다. 러너가 남긴 lock은 force-unlock 한다.

이관은 복사가 아니다. ECR, ACM, OIDC, Access Entry를 새 계정 값으로 다시 맞춰야 했다.

## 9/22 새 계정에서 다시 올리기

| 증상 | 원인 | 조치 |
|------|------|------|
| 노드그룹 `CREATE_FAILED` | NAT와 private 라우트가 노드보다 늦게 준비됨 | NAT·라우트를 먼저 기다리고, 고아 NAT IAM은 import, 실패 노드그룹은 삭제 후 재시도 |
| kubernetes/helm `Unauthorized` | 토큰이 15분에 만료 | `exec` + `get-token` |
| 이미 state에 있는 리소스를 또 import | import가 무조건 실행 | 있으면 skip |
| Terraform CI가 클러스터에 못 들어감 | CI 역할 Access Entry 없음 | ClusterAdmin Access Entry |
| ALB 주소가 계속 비어 있음 | ACM이 ISSUED 되기 전에 HTTPS annotation을 검 | ISSUED 이후에만 HTTPS를 붙임. 이게 ALB가 안 생긴 직접 원인 |
| Argo Missing, `terminatingReplicas` ComparisonError | ServerSideApply가 남아 있음 | 설치 후 ServerSideApply 제거 |
| db-restore Job이 Missing | sync-wave가 Ingress Progressing에 막힘 | sync-wave 제거 |
| 복구 직후 앱이 시크릿 없이 뜸 | Secret보다 Argo/Helm이 먼저 시작 | 복구 전에 `aniverse-app-secrets`를 넣음 |
| 워크플로를 다시 눌러도 이전 런이 남음 | `cancel-in-progress`가 꺼져 있음 | 켜서 이전 런을 취소 |
| 워크플로가 시작부터 실패 | `cancelled()`를 `run` 스크립트 안에서 호출 | 조건은 step `if`에만 둠 |
| Missing 대기가 약 8분 | 실패를 너무 오래 기다림 | 약 1분 안에 끊고 상태를 출력 |

앱 저장소에서는 새 계정 ECR 주소와 ALB HTTPS annotation을 되돌렸다.

## 9/23 화면과 데이터가 어긋남

### Actions는 초록인데 시드가 없음

- 증상: db-restore 검증은 통과인데 거래·작품 행이 0.
- 원인: 테이블만 있으면 Skip한다. migrate가 빈 스키마를 만든 뒤에도 Skip될 수 있다.
- 조치: 테이블 수가 충분해도 시드 행이 0이면 SQL을 다시 넣는다. 검증은 시드 행이 1 이상일 때만 통과. 차트 브랜치는 `app_ref`로 고른다.

### OutOfSync를 다운으로 봄

- 증상: 이미지 태그 bump 뒤 Argo가 OutOfSync.
- 원인: Git의 `image.tag`와 클러스터가 잠시 다르다. Healthy면 서비스는 떠 있다.
- 조치: 태그 bump 뒤에 sync를 한 번 더 건다. Healthy이면 OutOfSync를 실패로 보지 않는다.

### bind-domain이 시크릿을 비움

- 증상: 도메인을 다시 묶은 뒤 파드가 빈 설정으로 뜬다.
- 원인: `eks-bind-domain`의 helm upgrade가 라이브 Secret을 덮어쓴다.
- 조치: upgrade할 때 라이브 시크릿을 다시 주입한다.

## 9/28 ~ 9/29 켰다 끄기

- 증상: 새 apply가 Access Entry `ResourceInUse`. stop이 인스턴스 0으로 끝나는데 노드가 남아 있다. start 직후 kubectl이 `pipefail`로 죽는다.
- 원인: bootstrap이 만든 Access Entry와 Terraform이 같은 엔트리를 만든다. stop 대수가 `Terminating:Wait`를 빼면 아직 안 죽은 노드를 0으로 센다. 노드 Ready 전에 kubectl을 친다.
- 조치: Access Entry가 있으면 재사용한다. stop은 Terminating 포함 대수를 센다. start는 ASG InService 뒤에 kubectl을 실행한다.

## 발표용으로 남길 문장

1. 첫 로그가 원인인 경우가 적다. Block은 start 실패처럼 보였고, 실제는 키 유출이다. ALB가 빈 것은 Argo 고장이 아니라 ACM이 ISSUED 전이었다.
2. Actions 초록은 시드 복구 완료가 아니다. 스키마만 있으면 Skip되고 행은 0일 수 있다.
3. Argo OutOfSync여도 Healthy면 서비스는 떠 있을 수 있다.
4. SQL과 사진 파일은 따로다. 목록이 나와도 S3 sync가 빠져 있으면 이미지가 없다.
5. 노드를 끄려면 `maxSize=0`이 아니라 Launch suspend와 desired 0이다.
