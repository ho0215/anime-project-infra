| 증상 | 원인과 수정 |
|------|-------------|

| Helm `--set` 호스트 목록이 쉼표에서 잘림 | values 파일로만 전달 |

### 9/18 계정 Block과 destroy

- Block 원인은 EKS start 스크립트가 아니다. iac-admin 장기 키가 유출된 뒤 승인되지 않은 RunInstances가 나가면서 계정 `679583587966`이 막혔다. 이후 운영 계정은 `841535407395`다. 키 값은 문서에 적지 않는다.
- 막힌 계정에서 destroy가 중간에 죽자 남은 리소스가 다음 plan을 막았다.
  - 고아 ALB, 노드 Access Entry를 destroy 전에 치우는 preflight
  - `DELETE_FAILED` 노드그룹은 ReplaceUnhealthy를 다시 켠 뒤 ASG와 CloudFormation으로 삭제
  - VPC 삭제 전에 ENI를 지우고 타임아웃을 늘림. `aws_vpc`의 미지원 timeouts 블록은 제거
  - 러너가 남긴 S3 state lock은 force-unlock

이관은 복사가 아니다. ECR, ACM, OIDC, Access Entry의 ARN과 계정 ID를 새 계정 값으로 다시 맞춰야 했다.

### 9/22 새 계정에서 클러스터를 다시 올리기

| 증상 | 원인과 수정 |
|------|-------------|
| 노드그룹이 `CREATE_FAILED` | private 라우트와 NAT가 노드보다 먼저 Ready 되게 순서를 고정. 고아 NAT IAM은 import, 실패 노드그룹은 삭제 후 재시도 |
| kubernetes/helm 토큰이 15분에 만료 | `exec` + `get-token`으로 변경 |
| 이미 state에 있는 리소스를 또 import | CD에서 있으면 skip |
| Terraform CI 역할이 클러스터에 못 들어감 | ClusterAdmin Access Entry |
| Argo/Helm 복구 중에 ALB가 안 생김 | ACM이 ISSUED 이기 전에는 HTTPS annotation을 걸지 않음. 이게 ALB가 비는 직접 원인이었다 |
| Application이 Missing / ComparisonError | 남아 있던 ServerSideApply를 제거. `terminatingReplicas` 비교 오류도 같이 해소 |
| db-restore Job이 Ingress Progressing에 막힘 | sync-wave를 제거 |
| 시크릿이 비어 앱이 기동 실패 | Argo/Helm 복구 전에 `aniverse-app-secrets`를 넣도록 워크플로를 바꿈 (이후 시드 방식은 팀 작업으로 교체됨. 이 문서의 범위는 9/22 당시 복구 경로) |
| 같은 워크플로가 겹쳐 돌아 복구가 꼬임 | `cancel-in-progress` |
| `cancelled()`를 `run` 스크립트 안에서 호출 | 식은 step의 `if`에만 둔다 |
| Missing 대기가 약 8분 | 약 1분 안에 실패하고 로그를 남기게 단축 |

앱 쪽에서는 새 계정 ECR 주소와 ALB HTTPS annotation을 되돌렸다.

### 9/23 데이터는 있는데 화면이 비는 경우

- Actions가 초록이어도 시드가 비어 있을 수 있다. 스키마만 있고 시드 행이 0이면 Skip하지 않고 SQL을 다시 넣는다.
- 검증은 시드 행이 1 이상일 때만 통과. 차트 ref는 `app_ref`로 고를 수 있다.
- `image.tag`를 올린 뒤 Argo sync를 한 번 더 건다. Healthy이면 OutOfSync는 배포 실패로 보지 않는다.
- `eks-bind-domain`의 helm upgrade가 라이브 시크릿을 빼먹으면 파드가 빈 값으로 뜬다. 업그레이드 시 시크릿을 다시 주입한다.

DB 복구 조건은 이렇다. 테이블 수가 최소 이상이고 시드 행이 0보다 클 때만 Skip한다. SQL 복구와 media/static S3 동기화는 별개라, 목록이 돌아와도 사진이 없으면 S3 sync를 따로 본다.

### 9/28 ~ 9/29 켰다 끄기

- 새 apply에서 bootstrap이 만든 Access Entry와 Terraform이 같은 엔트리를 만들려다 `ResourceInUse`. 이미 있으면 재사용하게 바꿨다.
- eks-stop은 `Terminating:Wait` 인스턴스도 대수에 포함한다. 빼면 아직 안 죽은 노드를 0으로 착각한다.
- eks-start는 ASG InService를 기다린 뒤에 kubectl을 친다. 노드가 없을 때 파이프가 `pipefail`로 죽는 것을 피한다.

## 발표할 때 같이 말할 함정

1. 로그에 보이는 첫 에러가 원인인 경우가 적다. Block은 start 스크립트가 아니라 키 유출이었다. ALB가 빈 것은 Argo가 고장난 것이 아니라 ACM이 아직 ISSUED가 아니어서였다.
2. Actions 초록은 시드 복구 완료가 아니다. 스키마만 있으면 Skip되고 행은 0일 수 있다.
3. Argo가 OutOfSync여도 Healthy면 서비스는 떠 있을 수 있다. Missing은 ServerSideApply 잔여와 ACM 대기, 두 갈래가 있었다.
4. SQL을 넣어도 이미지·첨부는 S3에 따로 있다.
5. 노드를 끄려면 `maxSize=0`이 아니라 Launch suspend와 desired 0이다.
