1. 맡은 역할 한눈에

왜 중요? 장애·배포 시 “누구 것?”이 바로 정해짐

박서이Network & Security
VPC·SG·NAT → 사고 범위 축소
강유민Compute & Traffic

김윤주Data & Storage
RDS·EFS·S3 → 데이터 보존
김현우DevOps & CI/CD
조립·Actions → 자동·안전한 반영

2. 온프레미스에서 어려웠던 점

왜 중요? “왜 클라우드/자동화로 갔는지” 설득의 출발점

어려움현장청중 피해
수동 배포서버 4대 SSH실수=전체 영향
환경 불일치내 PC OK / 서버 NG원인 찾기에 시간 소모
확장·복구손으로 서버 증설장애 시 장시간 다운
비밀키 관리.env 서버 방치유출 리스크

3. Terraform 인프라

왜 중요? 인프라가 ‘기억’이 아니라 재실행 가능한 설계도가 됨

  • Network → ALB/Traffic → ASG Compute → RDS/EFS/S3
  • 모듈 분담 후 environments/dev에서 조립
  • + Secrets · WAF · HTTPS · Redis · CodeDeploy

4. GitHub Actions

왜 중요? 배포 방법이 사람마다 다르지 않고 로그가 남음

  • infra 저장소 → Terraform apply
  • app 저장소 → S3 zip → CodeDeploy
  • 흐름: push → 검증 → 배포 → aniverse.my

5. CI/CD · HA · 모니터링 · 보안

왜 중요? 배포해도 안 죽고, 사고는 빨리 보이고, 노출은 줄어듦

CI/CD헬스체크로 배포 판정, 실패 시 로그 추적
HAALB+ASG — 서버 1대 장애 ≠ 전체 다운
모니터링CloudWatch·SSM — 항의보다 지표가 먼저
보안SG·Secrets·HTTPS·WAF·Private Subnet
