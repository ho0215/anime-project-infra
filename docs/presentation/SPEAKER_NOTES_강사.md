## 슬라이드별 멘트 (읽기용)

### 표지
“오늘은 온프레미스 3-tier 서비스를 AWS로 옮긴 과정입니다.  
**청중에게 중요한 건** ‘클라우드를 썼다’가 아니라, **배포·장애·보안이 예측 가능해졌는지**입니다.”

### 1. 역할
“역할을 나눈 이유는 멋이 아니라 **책임 범위** 때문입니다.  
망은 서이, 트래픽·서버는 유민, 데이터는 윤주, 조립·자동화는 현우입니다.  
장애가 나면 **어디를 보면 되는지** 바로 알 수 있습니다.”

### 2. 온프렘 어려움
“예전엔 배포가 SSH와 기억에 의존했습니다.  
환경이 조금만 달라도 원인 찾기에 시간을 다 썼고, 서버 한 대 문제는 곧 전체 장애였습니다.  
**그래서** 코드와 파이프라인이 필요했습니다.”

### 3. Terraform
“Terraform으로 VPC부터 ALB, ASG, RDS, S3까지 **모듈로 나눠 만들고 조립**했습니다.  
**중요한 점:** 인프라가 문서가 아니라 **다시 실행할 수 있는 설계도**가 됩니다.”

### 4. GitHub Actions
“인프라는 apply, 앱은 CodeDeploy로 나눴습니다.  
**중요한 점:** 배포 방법이 사람마다 다르지 않고, 로그가 남습니다.”

### 5-1. CI/CD · HA
“헬스체크로 배포 성공을 판정하고, ALB+ASG로 **한 대가 죽어도** 버팁니다.  
사용자 입장에선 ‘업데이트했는데 사이트 전체 다운’이 줄어듭니다.”

### 5-2. 모니터링 · 보안
“CloudWatch·SSM으로 상태를 보고, Secrets·HTTPS·WAF·Private Subnet으로 노출을 줄입니다.  
**중요한 점:** 문제가 사용자 항의보다 **먼저** 보이고, 키가 서버에 흩어지지 않습니다.”

### 결과·마무리
“Before는 손으로 지키던 서버, After는 코드와 자동 배포입니다.  
역할 분담 + Terraform + Actions로, 지금은 aniverse.my 를 운영합니다.”

## 강사가 듣고 싶어 하는 포인트 (채점 감각)

1. **왜 옮겼는지** (고통)이 구체적인가  
2. **누가 무엇을** 했는지 한눈에 보이는가  
3. Terraform/Actions가 **도구 나열이 아니라 효과**로 설명되는가  
4. HA·보안·모니터링이 **사용자 피해 감소**와 연결되는가  
5. 5~7분을 **넘기지 않고** 결론이 분명한가
